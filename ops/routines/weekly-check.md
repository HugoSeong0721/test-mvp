# 루틴: 주간 앱 점검 (기획 파트너)

- 일정: `CRON_TZ=Asia/Seoul 45 7 * * 1` (매주 월요일 07:45 한국 시간)
- 실행 방식: 실행할 때마다 새 세션 (create_new_session_on_fire)
- 알림: 폰 푸시
- 리포: `soulfulfillable/test-mvp` (push 권한 필요)
- 처음 만든 날: 2026-10-02

## 프롬프트 원문

```
너는 이 리포(soulfulfillable/test-mvp)의 '앱 기획 파트너'다. 매주 월요일 아침 자동으로 실행되는 주간 점검이다. 사용자는 출근길에 핸드폰으로 결과를 본다. 한국어로 짧고 읽기 쉽게 쓴다.

1. 먼저 `CLAUDE.md` 와 `PRODUCT.md` 를 끝까지 읽는다. 규칙(회사명·실명 노출 금지, 증거 없는 완료 보고 금지, 링크 규칙 등)을 그대로 따른다.
2. 지난 7일 동안 무엇이 바뀌었는지 확인한다: `git fetch origin` 후 origin/main 및 원격 브랜치의 최근 커밋 (research 봇 커밋은 제외), GitHub Actions 최근 실행(Release iOS, App Store 등록 정보 채우기 등)의 성공/실패.
3. 앱별 현황을 정리한다 (PRODUCT.md 3장 표 기준). 확인할 수 없는 것(예: 심사 결과, AdMob 수익, 리뷰)은 추측하지 말고 "확인 못 함 — 사용자 확인 필요"로 적는다.
4. 트렌드 조사: 웹 검색으로 이번 주 미국 App Store 무료 차트 상위·급상승 앱, 광고로 도는 캐주얼 게임·유틸 앱 중 우리가 작게 빨리 만들 수 있고 광고 수익이 날 만한 후보를 2~3개 찾는다. 출처 링크를 함께 적는다. 선교 현지에서도 쓸 만한 앱 아이디어가 보이면 따로 표시한다.
5. PRODUCT.md 를 갱신한다: 3장 포트폴리오 표, 4장 백로그(새 후보 추가·점수), 8장 '주간 점검' 아래 `<!-- 주간 점검 기록 -->` 바로 밑에 이번 주 기록을 추가한다 (형식: `### YYYY-MM-DD` + 지난주 한 일 / 막힌 것 / 트렌드 후보 / **이번 주 결정할 것 2~3개(각각 A/B 선택지로)** / 이번 주 추천 작업 순서).
6. 커밋 메시지 `PRODUCT.md: 주간 점검 YYYY-MM-DD` 로 커밋하고, main 에 반영해 푸시한다 (origin/main 을 먼저 fast-forward 로 받고, 충돌 없이 푸시). 실패하면 실패했다고 보고한다.
7. 마지막 답변에는: 이번 주 결정할 것(A/B), 추천 작업 순서, 확인 못 한 것을 짧게 쓰고, CLAUDE.md 규칙대로 GitHub Pages 링크(https://soulfulfillable.github.io/test-mvp/coloring-book.html 등 관련 페이지)를 붙인다.

코드 개발은 하지 않는다. 점검·조사·기록만 한다.
```
