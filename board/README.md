# board/ — 세션끼리 공유하는 게시판

앱마다 개발 세션이 따로 돈다. 각 세션은 **자기 앱 파일 하나**(`board/<앱>.md`)만 고치고, 다른 세션 파일은 읽기만 한다
(파일을 나눠야 여러 세션이 동시에 푸시해도 충돌이 안 난다). 🧭 기획 파트너가 전체를 읽고 방향을 잡고,
여러 앱에 통하는 교훈은 `PLAYBOOK.md` 로 옮긴다.

## 개발 세션이 할 일

- **시작할 때**: `board/` 의 모든 파일을 읽는다 — 특히 다른 세션의 "다른 세션에 알리는 노하우"와 "사용자 성향".
- **언제 쓰나**: ① 사용자가 피드백을 줄 때마다(원문 그대로) ② 단계가 끝날 때마다 ③ 막혔다가 풀었을 때 ④ 세션 끝나기 전.
- 쓰고 나면 바로 커밋·푸시하고 main 에도 반영한다 (fetch → merge → push. 충돌 나면 양쪽 내용 모두 살린다).
- 공용 파일(`.github/workflows/*`, `PLAYBOOK.md`, `CLAUDE.md`, `PRODUCT.md`)을 크게 고치기 전에는
  `board/_shared.md` "공용 작업 중" 표에 먼저 적는다. 다른 세션이 이미 잡고 있으면 그 세션 결과를 기다리거나 재사용한다.

## 앱 파일 양식 (`board/<앱>.md`)

```
# <앱 이름> — 개발 세션 게시판
마지막 갱신: YYYY-MM-DD HH:MM (KST)

## 지금 상태 (3줄 이내)
## 다음 할 일 / 사용자에게 받을 것
## 사용자 피드백 기록 (최신이 위, 원문 인용 + 어떻게 반영했나)
## 사용자 성향 — 원하는 것 / 불편해하는 것 (이 앱에서 알게 된 것)
## 다른 세션에 알리는 노하우 (다른 앱에서도 써먹을 것)
## 다른 세션·기획 파트너에게 묻고 싶은 것
```
